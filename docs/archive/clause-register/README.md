# Archived clause register (2026-11-11)

These files are **retired working data**. Nothing in the repository reads them; they are kept
because their unmigrated columns may still help a reviewer trace an old decision. The live data is
the knowledge base itself: every classified record declares its `clauses`
(see [Clauses](../../reference/knowledge-base.md#clauses)) and
`python tools/knowledge/clauses.py` reports the inventory and its test coverage.

| File | What it was |
| --- | --- |
| `clause-contracts.csv` | The clause register: 4,538 rows keyed by `(id, clause_id)` with printed text, scope, semantic contract, effect relation, code consumers, verification references, notes and per-backend status. |
| `source-scope-review.csv` | The scope review of 3,394 source prose nodes (notes, restrictions, references) consumed only by the retired `check report rules` export. |
| `migration-report.json` | Machine-readable record of the migration below: every re-keyed clause, every unmigrated row, the markers added and the scaffolds renamed. |

## What moved into the knowledge base

| Register content | Destination |
| --- | --- |
| `clause_id`, `clause_scope` | `clauses: [{id, scope}]` on the effect, core rule, mechanic or item the row described, kept only where a record splits into several parts or excludes one (607 identities, 1,114 clauses); the 1,588 single-`whole` identities are undivided obligations. `semantic_contract` was dropped from the knowledge base the same day (see `clause-split-2026-11-11.json`): the observable a test checks belongs next to the test, and the register column stays here for re-authoring. |
| Scope decisions for the six catalogue skills that had no runtime block (`skill.chosen-of-the-white-tower`, `skill.instinctive-warrior` pending in scope; `skill.fey`, `skill.magic-resistant`, `skill.taunt`, `skill.trading-flair` out of scope) | `runtime` blocks in `catalog/skills/warband.yaml`. |
| `verification` references of kind `executed` that name a test function still present | `@pytest.mark.covers(identity, *clause_ids)` on 77 test functions. |
| E2E identities whose effect id had been renamed in the KB (220 identities, 295 clauses) | The scaffolds and scenarios were re-keyed to the current effect id; the mapping is listed below. |

## What was not migrated, and why

| Rows | Reason |
| --- | --- |
| 1804 | source/ rows (JSON-pointer or reference-only records; no E2E consumer) |
| 32 | clause NO on an effect already classified NO (the effect reason covers it) |

Columns dropped deliberately: `clause_text` and `source_fingerprint` duplicate the KB prose the
clause now sits next to; `effect_id`, `relation`, `parameters` and `conditions` restate the runtime
binding or were free-form analysis notes; `consumer` listed code paths that drift (36 already
dangling); `pending` and `status` were defaults in all but eight rows; `notes` is T13 review history.
195 `executed` references named only a file or a test that no
longer exists and could not become markers; they remain in `clause-contracts.csv`.

Clause placement followed the current knowledge base: a row whose effect id still exists kept it;
otherwise the clause went to the rule's single effect, to the effect whose binding id the row named,
to the only `YES` (or only `NO`/`LATER`) effect matching the clause scope, or to the hand-reviewed
target below. The E2E scaffolds that named a moved identity were renamed and re-keyed per scenario.
