## Inicio y coordinación

- Preparación tras T06; implementación tras T08 cerrado y T07 integrado.
- Paralela a T09 únicamente con archivos disjuntos. Core, loaders, bindings, esquemas y manifiestos requieren propietario único asignado; detener la escritura conflictiva hasta sincronizar.
- Leer [README de coordinación](../README.md). Solo el coordinador modifica la checklist principal. Base histórica `9118ca2` en `origin/2A2B`; trabajar sobre HEAD asignado.
- Propiedad candidata: dominio/servicios de campaña Python y TypeScript y sus pruebas; concretar módulos antes de editar. Cambios de UI y KB necesitan acuerdo con sus propietarios.

## Objetivo y lecturas

Automatizar todos los efectos asignados aplicables a reclutamiento, contratación, costes, mantenimiento, equipo, experiencia, avances y posbatalla. Revisar NO/LATER antiguos; una limitación del duelo no excluye campaña.

Leer `docs/guides/campaign-knowledge.md`, `packages/python/knowledge/mordheim_knowledge/campaign.py`, `packages/python/campaign/mordheim_campaign/`, `packages/typescript/application/campaign/service.ts`, `packages/typescript/domain/campaign/kernel/` y las suites `tests/python/campaign/`, `tests/python/application/`, `tests/typescript/application/campaign/`, `tests/typescript/domain/campaign/`.

La KB guarda reglas inmutables; la campaña guarda recursos, elecciones, tiradas e historia. Mantener el recorrido cargador → servicio → dominio/persistencia → UI y la transacción validada existente, sin reconstruir reglas en componentes.

## Pasos

- [ ] Extraer IDs, fuentes, casos y exclusiones concretas de T06; dividir efectos compuestos que tengan una parte de campaña aplicable.
- [ ] Trazar cada operación en ambos productos y localizar su mecanismo actual: costes, requisitos, efectos tipados, procedimientos, decisiones o tablas.
- [ ] Identificar diferencias previas entre Python/TypeScript y establecer el resultado requerido por la fuente; no tomar automáticamente un producto como correcto.
- [ ] Añadir casos mínimos a suites existentes antes de ampliar mecanismos de recursos, historial o transacciones.
- [ ] Usar campañas de prueba y fixtures aisladas para fallos y cancelaciones; no corromper temporalmente archivos de campaña o KB compartidos para probar rechazo.
- [ ] Implementar en dominio/servicio la activación y sus condiciones; exponer opciones mediante puertos existentes. No imponer reglas únicamente en UI.
- [ ] Aplicar costes/recompensas una sola vez, validar disponibilidad y evitar estados parciales si falla una operación; preservar cancelación y reintento del flujo actual.
- [ ] Inyectar tiradas y decisiones. Probar límites, ausencia de regla, recursos insuficientes, excepciones de perfil/banda y consumo de efectos temporales.
- [ ] Completar el mismo comportamiento en Python y TypeScript donde exista el flujo; verificar observable y persistencia, no solo igualdad de nombres.
- [ ] Coordinar nuevas elecciones o mensajes con el propietario de consumidores: ES/EN, accesibilidad, errores resueltos, cierre correcto de diálogos y resultado persistido visible.
- [ ] Verificar guardado/reapertura, historial y fases de campaña; campañas previas deben seguir cargando con sus IDs estables. No migrar esquema de archivo salvo necesidad demostrada y revisión del coordinador.
- [ ] Ejecutar `python tools/mordheim-utils.py tests --scope campaign`; desde `packages/typescript`, usar `npm test -- <filtro>` con filtros verificados y `npm run typecheck`.
- [ ] Revisar que los filtros seleccionan realmente casos; cero pruebas no constituye aprobación. Coordinar tests de UI con su propietario.
- [ ] Actualizar cobertura de efectos y marcas runtime solo con evidencia y propiedad asignada; entregar cambios compartidos antes de liberar a validación conjunta.

## Fin y evidencia

Todos los efectos de campaña incluidos en T06 se ejecutan en los flujos actuales con decisiones, recursos y persistencia correctos, en ambos productos cuando corresponda. Entregar casos por ID, resultados Python/TypeScript, prueba de reapertura y dependencias UI aún pendientes. No cerrar si una elección necesaria existe solo como helper o falta su recorrido de usuario.
