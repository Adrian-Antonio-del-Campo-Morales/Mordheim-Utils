## How agents maintain this document

1. Search by canonical ID, question ID and affected consumer before adding an
   entry. Update an existing entry when the same problem recurs; retain its ID.
2. Record the originating step, exact affected entities, observed behavior,
   reason for deferral, durable evidence/reproducer, accountable owner, target
   lot, resume condition and closure evidence. Say **unassigned** when no executor
   has been assigned; a lot name alone is not an assignment or a calendar date.
3. Distinguish a defect, a source decision, a missing proof and a deliberately
   gated handoff. Do not list every unimplemented rule already in the plan.
4. Use `open`, `blocked`, `in review`, `resolved`, or `dismissed`. Resolve only
   with evidence and coordinator acceptance; an implementation flag or a passing
   unrelated suite does not close an entry. A dismissal needs an explicit ruling.
5. Keep source interpretations in the existing `T13-Q` ledger/specifications;
   link them here rather than creating a competing decision. A proposed lot may
   be changed by the coordinator, with a reason retained in the entry.
6. This shared file needs coordinated writes. Include it in the file reservation
   when dispatching an agent. If another agent owns it, supply the complete entry
   in the handoff for the coordinator to insert; never overwrite concurrent work.
   The coordinator assigns non-overlapping IDs when concurrent dispatches need them.
7. Before accepting a lot, the coordinator checks that all deferred findings in
   its handoff are represented here or explicitly linked to an existing entry.
   Before starting a lot, inspect entries whose **Resume** condition it satisfies.
8. A finding is not automatically a separate assignment. Bundle its repair,
   cases and necessary documentation into the next functional family that owns
   it. Record a concrete observed gap or admitted blocked clause; hypothetical
   extra variants and already-declared exclusions do not require fresh projects.
