# T14 — Validación y paridad de combate

## Inicio y coordinación

- Pertenece a la fase 3 y empieza tras aceptar T13.
- Valida la revisión exacta de T13. Los defectos vuelven a su propietario; una corrección invalida solo los casos afectados.
- Propiedad: validación semántica, paridad y reporte. No alterar reglas ni crear otro framework durante la revisión.

## Objetivo

Demostrar que todas las obligaciones de Combat Simulator producen la semántica acordada y mantienen paridad determinista entre los backends aplicables. Esta tarea no vuelve a validar los flujos Web cerrados en T12.

## Existing shared construction boundary

Read [shared eligibility](../../../reference/eligibility.md#construction-boundary-for-phased-implementation)
and the [current integration routes](T13-T15-remaining-plan.md). T14 does not
certify a newly written constructor: both products already use the shared
decision module. Reuse current bundle/direct/embedded evidence and F035's
per-finding dispositions; separately verify canonical bindings, compiled effects
and their actual engine behavior. Legality, executable support and backend
parity are distinct claims. Revalidate affected Web paths only when a shared
decision/fact change actually invalidates their accepted evidence.

## Pasos

Use the functional-family batches in the [current remaining plan](T13-T15-remaining-plan.md).
T14 is the independent certificate of the accepted final delivery, not another
investigation of every unchanged handoff. Reuse matching source/contract and
case evidence, run the required current semantic/parity gates, and independently
challenge material semantics and actual backend execution. Repairs invalidate
their affected evidence; no extra test-only project is created for hypothetical
variants or optional tool improvements. Missing applicable proof still blocks
its required acceptance.

- [ ] Mapear cada obligación de combate T06 a implementación, especificación, prueba y backend aplicable.
- [ ] Check F035 current dispositions and matching shared-module/bundle/consumer evidence; return reproduced legality defects to the shared owner and combat projection defects to the compiler owner.
- [ ] Probar activación, no activación, límites, coste/estado, decisiones, errores, duración y composición relevante.
- [ ] Comparar backends con las mismas entradas, decisiones y dados.
- [ ] Exigir el mismo orden lógico de RNG y estado observable; no conformarse con probabilidades parecidas.
- [ ] Confirmar que el backend nativo corresponde al código actual y no a una extensión antigua o fallback.
- [ ] Ejecutar regresiones de reglas anteriores afectadas por mecanismos compartidos.
- [ ] Mantener explícitas las exclusiones de despliegue, ocultación, disparo y magia de batalla; no ampliarlas para cerrar fallos.
- [ ] Declarar cualquier backend no disponible como pendiente, nunca aprobado.
- [ ] Reconciliar todas las obligaciones `Combat Simulator` de T06; ninguna queda respaldada solo por prosa o metadata.
- [ ] Entregar matriz regla/caso/backend/resultado y limitaciones a T15.

Todas las obligaciones de combate incluidas tienen evidencia semántica y paridad en cada backend aplicable; no quedan defectos funcionales pendientes. Entornos ausentes se declaran como validación pendiente y bloquean el cierre correspondiente.
